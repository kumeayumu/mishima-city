The patch omits the event-time faction filter, can present contradictory official-result notices, and allows unmapped source marks to become definite participation claims. Lint and type checking passed; the full test run was not confirmed.

Full review comments:

- [P2] Filter votes by faction at the time of each vote — F:/mishimacity/mirai-gikai-mishima-migration/web/src/features/council-activity/server/components/vote-list-view.tsx:105-113
  The filter form has no faction control, so readers cannot compare votes by the faction recorded for each event. This matters for members such as Tsuchiya, whose May and September affiliations differ: a profile-level faction filter would misclassify one of those votes. Use the event affiliation for each cell and distinguish cells outside the filter from missing votes, as specified in the [STEP 3 plan](docs/20261125_1643_STEP3議員別議案賛否の実装計画.md#L168).

- [P2] Update the coverage notice when official results are published — F:/mishimacity/mirai-gikai-mishima-migration/web/src/features/council-activity/server/components/vote-shared.tsx:24-28
  When a November result check changes to `published`, `getVoteBills` displays the new official result, but this notice still says that all 18 November bills lack an official decision date and result. It also uses the first check's date for all 18, even if the checks were made on different days. Derive the outstanding count and date wording from the actual checks so the notice does not contradict the result shown on the same page.

- [P2] Reject unmapped source marks before assigning participation — F:/mishimacity/mirai-gikai-mishima-migration/web/src/features/council-activity/shared/utils/vote-data.ts:234-235
  An unrecognized `observedMark` with `choice: null` can pass validation as an absence, abstention, recusal, or other non-voting state because the participation check only runs when the mark is in `states`. A transcription typo can therefore become a definite public claim about a council member. Reject unmapped marks or require them to be represented explicitly as `unknown`.

- [P3] Keep vote review labels consistent after approval — F:/mishimacity/mirai-gikai-mishima-migration/web/src/features/council-activity/server/components/vote-shared.tsx:49-51
  Once independent and operator review are approved and the publication guard allows a hosted release, this heading still says independent review is pending, while the coverage notice says it is complete. The member vote history also always says both reviews are pending. Derive these labels from the verification state so readers see the same status on the detail and member pages.

- [P3] Make the vote matrix scroll region keyboard-focusable — F:/mishimacity/mirai-gikai-mishima-migration/web/src/features/council-activity/server/components/vote-list-view.tsx:152-156
  The matrix can overflow both horizontally and vertically, but its named scroll region is not directly focusable. In browsers that do not automatically make scroll containers with focusable descendants keyboard-focusable, readers have to tab through cell links instead of focusing the region and scrolling it with the keyboard. Add a focus stop to the region as specified in the [STEP 3 accessibility plan](docs/20261125_1643_STEP3議員別議案賛否の実装計画.md#L166).
