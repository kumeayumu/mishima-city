## 2. 198セルを二重照合する具体的な手順

### A：一次抽出・資料固定

1. 公式掲載ページからPDFを取得し、取得日時、URL、ファイルSHA-256、PDF枚数・印刷頁、凡例、資料版を記録する。調査時から内容が変わっていれば差分を報告して再確認する。
2. 原PDFと画像・抽出作業ファイルはリポジトリ外の一時領域に保存する。公開フォルダー・Gitへ本文や紙面画像を追加しない。
3. PDFの文字・座標から氏名列と記号候補を抽出し、22人のIDへ対応させる。PDFごとに列順が違うので、同じ列番号を使い回さない。
4. 1セルごとに `(sourceVersion, 議案行, 議員列, 原記号, 正規化状態)` を記録する。斜線は文字抽出だけで消えるため、PDF画像の凡例と合わせて確認する。
5. 一次担当が原表を見ながら全198セルを確認し、A版を固定する。候補データは未承認として作業領域に置き、アプリへ自動投入しない。

### B：独立した二次照合

6. 別担当または運営者が、**Aの正規化結果を見ずに**同じ公式PDFから22人×9議案を独立に読み取る。機械抽出と同じ結果を眺めるだけ、同じOCRを再実行するだけでは二重照合としない。
7. 人手が1人の場合は、時間を分け、一次結果を隠した再入力を行い、その限界を記録する。Codexが2回読んだだけで「運営者による独立確認済み」とは扱わない。
8. A・Bを氏名列番号ではなく `(votingEventId, memberId)` で比較する。氏名、採決日、原記号、凡例、会派見出しも対象にする。
9. 不一致セルを公式原表に戻って解消する。凡例や字形を解決できなければ `unknown` とし、理由と未解決件数を表示する。賛成・反対へ寄せない。
10. 運営者へ198セルの差分表と資料リンクを提示し、最終校閲を依頼する。確認者・確認日・A/Bの結果・訂正理由を保存する。

## 4. 状態の区別・集計原則

| 表示記号案 | 状態 | 正規化の根拠 |
|---|---|---|
| ○ | 賛成 | 個人表で賛成が明示 |
| × | 反対 | 個人表で反対が明示 |
| 欠 | 欠席 | 当該採決の公式資料に欠席と明示 |
| 退 | 退席 | 退席と明示。理由・抗議等を推定しない |
| 棄 | 棄権 | 棄権と明示。退席と混同しない |
| 除 | 除斥 | 除斥と明示 |
| 議 | 議長による採決不参加 | 斜線等の凡例を確認 |
| ? | 不明 | 判読不能・資料の不一致等。理由と確認状況を表示 |
| 未 | 個人票は資料未掲載 | 全会一致等でも個人表がない。投票の事実ではなく資料状態 |
| 結果未掲載 | 議決結果が原本に未掲載 | 未採決・欠席・棄権と断定しない |
| 対象外 | 当時非議員等 | 今回の22人×9表には通常不要。将来拡張用 |

`VoteChoice` はyes/no/null、参加状態は別フィールド。賛成かつ欠席のような矛盾を検証で拒否する。「その他」の集計を表示する場合も、欠・退・棄・除・議・不明の内訳を残す。

賛否だけの比率は確認できたyes＋noを分母にし、その他・不明人数を併記する。在籍者構成を分母にする図は別の見方として分母を明示し、グラフには同値の表を付ける。投票数から議決結果を再計算しない。特別多数・議長裁決等は公式結果を優先する。
