# Windowsローカル開発手順（三島市版）

## 対象と方針

2026年11月15日。README内の別地域向けFork手順書を基準に、現在のコードとWindows環境へ合わせた手順です。
作業先はF:\mishimacity\mirai-gikai-mishima-migration、ブランチはmishima-migrationです。
元の福岡市版worktree、PR #1、議案62件・会議録7日分は保持します。PRをマージしません。

## 1. 最初に環境を準備する

このPCの通常のNode.jsはC:\Program Files\nodejsの26系です。pnpm・バージョン管理ツールは通常のPATH上にありませんでした。
他のプロジェクトがNode.js 26を使っている可能性があるため、アンインストール、グローバルPATH変更、npmのグローバルインストール、PowerShellプロファイル変更はしません。
他プロジェクトのフォルダーをPC全体にわたって走査したわけではありません。影響を避けるための隔離を採用します。

~~~powershell
Set-Location F:\mishimacity\mirai-gikai-mishima-migration
.\mishima.cmd setup
~~~

setupが行うのは以下だけです。

1. .node-versionに固定した公式Node.js 24.22.3のWindows ZIPを取得し、公式SHASUMS256.txtで検証して.tools内へ展開。
2. package.jsonのpackageManagerに固定したpnpm 10.34.9を.tools内だけへ導入。
3. .envがない場合だけ.env.exampleからコピー。
4. 固定版のpnpmでinstall --frozen-lockfileを実行。

既存の.envは上書きしません。DBへの接続・初期化・マイグレーション・seed投入は実行しません。
.toolsはこのworktree専用の通常フォルダーで、Git管理外です。一時キャッシュを消してもここに導入したツールは残ります。
初回に既存Node.jsを使うのは準備処理だけです。準備後はmishima.cmdがローカルのNode.js 24を優先します。

## 2. バージョンを確認する

~~~powershell
.\mishima.cmd info
.\mishima.cmd node --version
.\mishima.cmd pnpm --version
~~~

v24.22.3と10.34.9が表示されれば準備完了です。
通常のnode --versionが26系のままでも正常で、他プロジェクト用の環境はそのままです。
この方法ではグローバルpnpmを導入しないため、裸のpnpmではなくmishima.cmd経由で実行します。

## 3. 公開サイトを起動する

~~~powershell
.\mishima.cmd dev
~~~

Readyと表示されたら http://localhost:3002/ を開きます。
ターミナルを閉じずに使用し、終了するときはCtrl+Cを押します。
既に3002番で起動している場合は二重起動せず、既存のターミナルを使ってください。

このコマンドは公開サイトだけを起動します。元のpnpm devに相当する全サーバー起動はmishima.cmd dev:allで、管理画面の動作にはDB設定が必要です。
管理画面は3001番です。Docker・Supabaseは公開トップの開発表示には不要です。

.env.exampleのNEXT_PUBLIC_WEB_URLはhttp://localhost:3002です。既存.envは自動変更しないため、既存設定が3000等の場合は、他の値を消さずこの項目だけ実際の公開サイトURLに合わせてください。
.envには秘密情報が入るためGitへ追加しません。.env.exampleはローカル用のサンプルで、本番用の資格情報ではありません。

## 4. テスト・型チェック

~~~powershell
.\mishima.cmd lint
.\mishima.cmd typecheck
.\mishima.cmd test
~~~

Windowsの改行差によるlintエラーを防ぐため、このリポジトリは.gitattributesでテキストをLFに揃え、.cmdだけCRLFにします。
ユーザー全体のGit設定は変えません。
ツールの単体テストはWindows以外のCIでも実行可能です。checksumの不一致、PATHキーの重複、元の環境を変更しないことを検証します。

## 5. 現在の制限

- 本番ビルドは、停止対象の/committeesでDB取得が実行され、Supabase未起動だと失敗する課題が残っています。今回の環境整備とは別に修正が必要です。
- 既存postinstallのsimple-git-hooksは、worktreeの.gitがファイルのためENOTDIRを出す場合があります。共有Git hooksは勝手に書き換えず、上の品質チェックを手動実行します。
- .claude/settings.local.jsonは元から存在しないため、コピーしていません。サイト起動には影響しません。
- 現在のCIの対象ブランチは旧設定のままです。今回、packageManagerの固定版と競合しないようCIのpnpm版だけを合わせ、起動条件は変更していません。
- 管理画面・三島市専用DB・AI解説・運営者情報・OGP画像は未整備の部分があります。

## 6. DB作業は別の段階で行う

Docker DesktopとSupabase CLIは、DBや管理画面を検証するときに準備します。
既存seedには福岡市向けの情報が残り、既存のデータを消す処理もあります。
ユーザーの許可なくdb:reset、seed、Supabaseの初期化・DB push等を実行してはいけません。
今はこれらを実行しなくても公開サイトを確認できます。

## 7. 履歴

旧手順のNode.js 20以上、公開サイト3000番、福岡市版へのPR、Macのbrew等の記述を、そのまま本プロジェクトのWindows手順として使用しないでください。
元の資料は履歴として保持し、現在のREADME・AGENTS.md・本手順書を参照します。
PC全体の設定変更が必要になった場合は、他プロジェクトへの影響を説明し、実行前に確認を得ます。
