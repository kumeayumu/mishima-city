# データ抽出・照合・訂正の品質管理手順

作成：2026-11-26。対象：議員活動可視化。DB・AI有料API・公開設定を変更する手順ではない。

## 1. 資料固定と取得範囲

公式URL、取得日時、バイト列のSHA-256、紙面ページとPDF上のページ、会期・年度を保存する。HTMLの更新日や会期名だけで、個々の採決・発言の発生時点を確定しない。必要のない住所・年齢・会議録全文を新たな配布対象にしない。資料版が異なる場合は差分を調べる。

## 2. 採決・発言の時点と人物

議員IDを固定し、氏名と表記差は公式根拠を確認して対応する。名簿の役職や会派は日付のスナップショットであり、その日のすべての採決へ遡及しない。議長交代のある会期は会議録の採決、休憩、辞職、議長選挙、着席の順序を確認する。時刻が不明なら推測で分単位の就任時刻を作らず、発言ID等の順序を根拠にする。副議長の議事進行と議長職の在職期間も区別する。

今回の例：5月15日、承第5号の採決・宣告は発言64・65（堀江氏）。宮下副議長の再開は76、辞職許可は85、岡田氏当選は99、着席は101。5月15日の名簿に岡田議長とあることは、採決時の議長を示さない。

## 3. 一次抽出と画像確認を分離

1. PDFは氏名の列見出し・議案行・個々のセルを直接対応させる。元記号、出典位置、文字抽出値を保存する。
2. 文字抽出で斜線などの図形が欠落したセルはnull／未確認のまま残す。現在の議長名や前の会期の列番号、人数から埋めない。文字列の途中へ固定位置で「議」を挿入して完了扱いにしない。
3. 原本画像から別の表へ、氏名・列・記号を直接読み取る。文字抽出のセル配列をコピーして画像確認済みの配列を生成しない。画像の文字補完や生成AIによる描き直しも行わない。
4. 文字値と画像値が両方ある場合は照合し、不一致は停止する。文字がないが画像で明示的に確認できる場合は画像のみ確認と記録する。両方ない場合は推定で確定しない。
5. 同一AIの二方式照合は独立した二者確認ではない。判読不能・資料間不整合は、根拠が揃うまで未確認とする。

実装：vote-evidence.tsで欠落・不一致・画像のみ確認を区別。vote-cell-evidence.jsonで198セルの氏名ID・原表位置・文字値・画像値を保持し、アプリの票と1セルずつ検証する。これはCodexの再確認記録であり、別AIが独立に作成した原本ではない。

## 4. 独立AI照合と人の確認

- A：一次抽出を固定し、チェックサムと版を保存。
- B：別環境のAIへ公式資料だけを渡して独立抽出。一次データや画面を見せる前にCSVを確定・保存する。
- C：その後に両CSVを人物・議案・出典位置で対応させ、元記号、意味、参加状態、当時会派を比較。○／〇の字体差と賛否の意味差を分ける。
- D：人による最終確認は別ステータス。AI照合が完了しても人の確認・運営者承認・公開承認を自動的に完了しない。

別AIの結果が運営者から要約で報告された場合、実施済みという報告と件数を記録し、未受領の独立CSVをCodex側で作成したと主張しない。初版時点の別AI報告は訂正前196一致・2不一致だった。その後、同じ独立抽出済みCSVと訂正版をプログラム比較し198一致・0不一致、重複0、196セル不変との運営者報告を受領した。人の最終確認とは区別する。

## 5. 個人票と集計のテスト

人数・割合・全セル数の一致だけでは、議員間で票を入れ替えた誤りを検出できない。議員IDと議案ID、元記号と参加状態、原表の行列位置を直接テストする。賛成19・反対2・議長1のままでも、岡田氏と堀江氏の票を戻してしまった場合は失敗させる。議長列の図形欠落や、同日後刻の議長を採決へ遡及するケースも回帰テストへ追加する。全会一致から個人票を生成せず、未掲載を0票や欠席へ変換しない。

## 6. 不一致発見時の訂正履歴

発見日時・報告者の役割・元の版・旧値・訂正候補・一次資料・調査結果・変更承認を記録する。矛盾があれば公式照会の前にも承認を得る。元データ・過去記録を無断削除せず保存版へ退避し、現行資料の先頭に撤回・訂正と履歴へのリンクを付ける。訂正後は対象セルと非対象セルの両方を比較し、画面・個人履歴・CSV・検証台帳を同じ版に揃える。旧配布物は旧版として保持し再利用を防ぐ。

## 7. 今後の一般質問・行政答弁への適用

採決セルのキーを、会議ID・日付・発言ID・質問者ID・答弁者と役職・原文範囲へ置き換える。質問、答弁、再質問、再答弁の順序を維持し、同じ質問者の別議案・別所管へ答弁者や内容を横滑りさせない。発言者の交代や役職の変更を議事進行の根拠で管理する。要旨は原文の出典範囲と結び、原文抽出と要約を分離して独立確認する。件数一致を内容一致とせず、未取得を登壇0回と扱わない。ランキング・独自スコアは作らない。

この節は品質手順のみ。STEP 4以降のデータ取得機能・要旨生成・有料API・本文再配布は実装していない。転載条件と公開前監査は別途管理する。
