# Vercelテスト公開準備（2026-11-15）

## 原因と構成

`committees/layout.tsx`でnotFound()を呼んでも、Next.jsは子ページを並行に評価するため、`getCommitteeArchives()` → repository → Supabaseの取得が先に始まります。レイアウトでの公開停止だけではDB接続を防げませんでした。

今回はアーカイブだけをテスト公開する構成です。Next.jsのprivate folder規約（先頭アンダースコア）を使用し、既存ルートのソースを`web/src/app/_legacy`と`web/src/app/(main)/_legacy`へ保持移動しました。エラーをcatchして空データにする対応、ダミーDB認証情報、ビルド時のDB障害の無視は追加していません。DB・AI機能を復帰するときは、移動元へ戻すだけでなく三島市データ、認可、環境変数、実DBでの結合テストを確認します。AI設定フラグだけをtrueにしてもルートは復帰しません。

| 機能 | DB | 今回の公開範囲 |
|---|---|---|
| トップの議案・議決一覧、会議録詳細 | 不要。同梱JSON | 公開対象 |
| 利用規約・プライバシー・FAQ、sitemap、robots | 不要 | 公開対象。文面確認は必要 |
| DB版議案詳細、会期一覧、一般質問、検索 | 必要 | `_legacy`へ保持。URLは404 |
| AIチャット・インタビュー・意見・レポート・プレビュー・API | DB＋認証、AI機能は外部APIも必要 | `_legacy`へ保持。URLは404 |
| 委員会、予算、事務事業、記者会見、選挙 | DB依存または旧地域固有情報 | 三島市用未整備のため非公開 |
| 開発用ギャラリー | 検証用データを使用 | `_legacy`へ保持し公開対象外 |
| adminアプリ | DB＋認証等が必要 | 今回はデプロイ対象外 |

Supabase公開環境変数はDB機能のアクセス時に検証します。AI用匿名クライアントも実利用時に生成し、アーカイブの読み込みでは生成しません。実際にDBを使う場合の設定漏れ・接続失敗は引き続きエラーになります。

## main向けCI

Code Checkはmainへのpull_requestとpushで実行します。Nodeは.node-version、pnpmはpackageManagerと一致させます。lint、型チェック、カバレッジ付きテストに加え、DB認証情報を設定しない公開webビルドを実行します。

Supabaseを起動するIntegration Testsはworkflow_dispatchのみとしました。通常のPR検証ではDBを起動しません。手動結合テストは使い捨てのCI DBを作るため、実行前に内容と対象について許可を得てください。本作業では実行しません。main未マージの間はGitHubの手動実行一覧に現れない場合があります。

## Gitフック

simple-git-hooksが`.git/hooks`を直接作ろうとしていましたが、worktreeの`.git`はファイルです。postinstallを`node scripts/git/install-hooks.cjs`へ変更し、`git rev-parse --git-path hooks`でGit自身に保存先を問い合わせます。PC全体のGit設定やcore.hooksPathは書き換えません。既存の独自pre-commitは上書きせず保持します。

通常のworktreeではhooksが同じリポジトリ内で共有されます。生成するhookは実行時のチェックアウトでlint-stagedを起動し、Windowsではmishima.cmdによる固定ツールを使用します。既存のhookが保存されてインストールされない場合は、明示的なlint・型チェック・テストを品質ゲートにしてください。

CI/Vercel/Git管理のないソースではフックをインストールしません。lint-stagedはステージされたファイルだけをBiomeで確認・修正するよう変更しました（以前は全リポジトリのlint:fixを実行していました）。

VercelへGit連携するとpushにより自動デプロイされ得ます。公開の許可を得るまで接続・デプロイ操作をしません。既に連携済みの場合は、push前に自動デプロイの設定確認が必要です。
