## 原因候補（未確定）

- 保存済み認証の失効・取り消し・期限や、ブラウザとCLIで利用するアカウントの相違。
- トークンの対象スコープとkume-2819が一致しない、または対象プロジェクトへの読み取り権限不足。

ブラウザでログインできることと、CLIの保存済み認証でREST APIを利用できることは別である。これらは原因候補であり、個別に発生したと確認したものではない。

## 運営者が管理画面で確認する手順（表示の確認のみ）

1. Vercelへ通常どおりログインし、左上のチーム選択でkume-2819を選ぶ。mishima-city-webが見えるか確認する。見えなければ別プロジェクトを作成・Importせず、その時点で報告する。
2. プロジェクトのSettings → Generalで名前とProject IDを確認する。チーム側SettingsでTeam IDを確認できる場合は照合する。本人の役割・アクセスは表示確認にとどめ、権限を変更しない。
3. プロジェクトSettings → Deployment ProtectionでVercel AuthenticationがON、対象がAll Deploymentsであることを確認する。チーム既定の設定だけで判断せず、プロジェクト側の実効設定を見る。保存ボタンは押さない。表示が違う・選択できない場合は変更せず報告する。
4. 同画面のProtection Exceptions、Protection Bypass for Automation、利用可能ならTrusted IPs等を確認する。例外の有無・対象を記録し、秘密値・バイパスURLはコピーや報告に含めない。自動化バイパスの作成・再発行・削除をしない。
5. Deploymentsから既存デプロイを開いてShareを表示する。Only people with access等の設定と、Anyone with the link／追加共有の有無を確認する。共有リンクを新規生成しない。チームのDeployment Protection → Accessに共有リンク一覧が表示される場合は併せて確認する。UIの名称や利用可否はプラン・権限で異なるため、見つからなければ未確認と報告する。
6. Settings → GitでGitHubリポジトリが未接続であることを確認する。ConnectやImportは実行しない。
7. DeploymentsでProduction表示の対象を開き、Deployment ID、ソースSHA、Ready、Productionドメインの紐付けを確認する。上記の過去値と比較する。Promote・Redeploy・Rollback・Deleteは押さない。
8. SettingsのBuild and Deployment等でRoot Directory web、Next.js、Node24.x、Build Command pnpm run build、Install Command pnpm install --frozen-lockfile、Root外ファイルの参照設定を確認する。共有packagesを含むルートアップロード構成を維持し、未確認ならデプロイしない。
9. Environment Variablesは変数名・対象環境のみ確認し、値を表示・報告しない。PreviewのNEXT_PUBLIC_WEB_URLまたはVERCEL_URL利用、不要なAI／DB依存、MISHIMA_LOCAL_REVIEW・MISHIMA_CI_VERIFY等の迂回フラグがないことを確認する。追加・編集・削除はしない。
10. アカウントSettings → Tokens等で既存認証の名称・有効期限・対象スコープが表示される場合に確認する。秘密値は表示・転記しない。CLIと当該項目の対応が不明なら推測しない。再ログイン・トークン再作成・取り消し・権限変更が必要そうな場合は、その必要性を報告して別途承認を得る。

画面確認結果は「項目／現在値または有無／確認日時／未確認理由／過去値との差」の形式で記録する。スクリーンショットを残す場合は秘密値や共有・バイパスURLを含めない。

## Preview前の停止条件と確認方法

APIの403が未解消でも、保護設定を確認できたと報告しない。APIまたは管理画面で対象・Authentication／All Deployments・例外なし・Git未接続・Production不変等を確認し、確認方法と限界を記録してから実行承認を求める。現在はPreview未承認。

承認後のPreviewでは通常のLinuxビルドを使い、CI例外・ローカル確認フラグ・prebuiltでガードを迂回しない。発行URLとaliasごとに認証情報やバイパスを付けないHTTPアクセスでトップ・議員・議案・会議録・実在静的ファイル・API等を検証する。認証画面への遷移を確認し、404やnoindexだけで保護成立としない。認証後の本人画面確認とProduction不変確認を別途行う。

デプロイ失敗は停止・報告し、無断再デプロイしない。匿名漏えい時はURLを拡散せず、実行承認時に定める対象Previewの停止・削除等の権限と手順で対応する。プロジェクト全体停止は既存Productionにも影響するため、今回無断で実施しない。認証解除や一般公開の設定変更は行わない。
