### データ更新の具体的な運用案

1. 対象年度を2026年度のまま固定し、取得日時・対象範囲・出典・担当者を記録する。
2. 既存原本を上書きしない新しい取得先を用意する設計を先に行う。本文の保存先・公開範囲は権利判断に従う。
3. 公式情報との差分（新規・訂正・結果追加・消失）を一覧にする。消失した資料を自動削除しない。
4. 62件・7日という初回基準と、将来の更新後件数を区別する。現行テストの固定件数も承認した更新時に見直す。
5. URL、年度境界、議案番号と件名の不一致、結果未掲載、見出しを含む記録数を確認する。
6. 人が差分を承認後、配信用index・manifestを更新し、型チェック・テスト・lint・ビルド・非配信テストを実施する。
7. 変更と取得根拠を履歴化し、Previewで匿名保護とログイン後表示を検証する。反映頻度は定例会前後・議決結果公表時の手動確認から始める。

自動取得の定期化、上書き回避、差分プレビュー、公開メタデータと非公開本文の分離は今後の実装候補であり、既存スクリプトに備わっていると解釈しない。

## 6. 会議録の利用方針の比較

| 項目 | 公式リンク方式を維持 | 利用条件・許諾等を確認して本文利用 |
|---|---|---|
| 表示 | 開催日・会議名と公式へのリンク | 確認した範囲に限り本文・抜粋・検索結果等 |
| 検索 | 本サイトは開催情報検索。本文検索は公式サイト | 本文索引、該当箇所表示が可能になる見込み。条件次第 |
| 発言者・関連付け | 公開可能なメタデータと検証済みリンクを別途整備。本文機能を約束しない | 発言単位の構造化と人名・議案の関連を検証して整備 |
| 可視化 | 確認済みの日程・議決結果などの事実を中心とする | 論点や質疑の整理まで拡張可能だが誤要約・誤帰属の審査が必要 |
| 権利確認 | 表示メタデータ・リンク先条件も確認。リンク方式なら全て無条件に適法とは断定しない | 複製、再配布、索引、改変、抜粋、AI利用、保存期間、出典表記を個別確認 |
| 元データ管理 | 原本保持を続ける。アプリへの送信除外を維持 | 許可範囲外のデータを混ぜず、訂正・削除要請への手順を用意 |
| 費用・運用 | DB・有料AIなしで進めやすい | データ整備・検索基盤・品質保証が増える。AI導入は必須ではない |

現時点の推奨は公式リンク方式の継続。本文検索を小さな抜粋や索引に変えるだけで権利確認が不要になるとは扱わない。
三島市公式ホームページの利用条件は、法令上認められる利用を除く転載等について許可が必要と説明している。
ただし、この一般条件だけで別ドメインの公式会議録の具体的な再利用範囲を確定できない。会議録の転載・加工・再配布条件は未確認のまま。
AGPL v3はアプリコードのライセンスであり、第三者の会議録本文に自動適用されない。
