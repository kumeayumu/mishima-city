## Vercelの初回デプロイについての訂正

Vercel公式仕様では、新規プロジェクトの初回デプロイはProduction扱いです。mishima-migrationからの実行や--target=previewでも例外ではなく、Production用環境変数が使われます。GitHubのPRをマージしなくてもこの挙動になります。したがって「非mainブランチから実行すれば必ず初回からPreviewだけになる」という手順にはしません。

初回Productionの作成自体が許可されない場合はデプロイを停止し、別途手順についてユーザーの判断を得ます。承認なしに失敗用デプロイを作って回避することも行いません。

## 承認後に設定できる保護方式

推奨はVercel AuthenticationのAll Deploymentsです。Standard ProtectionはProductionドメインを除外するため、初回の限定公開には不足します。パスワード保護はプラン等による制約があるため、無料で必ず使える前提にはしません。All DeploymentsとVercel Authenticationの組合せは公式資料で全プラン対応を確認しました。閲覧者のVercelアカウント・アクセス権は事前に確認します。

Git Import画面で先にDeployを押す方法は使わず、次の順で準備します。以下は未実施の手順です。

1. アカウント・チームと対象プロジェクトを特定し、既存デプロイの有無を確認します。料金プラン・権限・保護設定が不明なら先に止めます。
2. 新規の場合は、Vercel REST APIのCreate a new project（POST /v11/projects）でGit連携を指定せずプロジェクト設定のみを作る方法を使えます。作成時のssoProtectionにdeploymentType: allを指定できます。このAPI操作にも別途承認を得ます。トークンはチャットやGitへ保存しません。
3. DashboardのSettings → Deployment ProtectionでVercel AuthenticationとAll Deploymentsを確認します。APIの場合はプロジェクト更新で下記JSONを設定し、GETで実際の値を読み戻します。

~~~json
{
  "ssoProtection": {
    "deploymentType": "all"
  }
}
~~~

4. 保護の例外・共有バイパスリンク・自動化用バイパスを不用意に作りません。独自ドメインは追加せず、Git連携も承認まで行いません。連携するとpushで自動デプロイされ得ます。
5. 以下のビルド設定を確認します。

| 設定 | 値 |
|---|---|
| Framework / Root Directory | Next.js / web |
| Include source files outside of Root Directory | 有効。packagesとlockfileを参照するため |
| Node.js / pnpm | 24.x / 10.34.9 |
| Install / Build Command | pnpm install --frozen-lockfile / pnpm run build |
| Output Directory | Next.js既定の.next |
| GitHub既定ブランチ | fukuoka-city/developのまま変更しない |
| Vercel Production Branch | mainを設定予定。ただしmainは旧版なのでデプロイ対象には選ばない |
| 公開するソース | mishima-migrationの承認済みコミットを特定 |
| NEXT_PUBLIC_WEB_URL | 実際のテスト用HTTPS URL。初回はProduction側、以後Preview側で必要な値を設定 |
| DB・AI・解析用キー | 設定しない。既存.envはアップロードしない |

6. 初回Production扱いと、認証付き限定公開の範囲について明示的な承認を得てから、対象コミットをデプロイします。初回にPreviewだけを指定したつもりで進めません。既存プロジェクトで初回が済んでいる場合はPreviewの対象環境を確認します。
7. 公開URLで、未ログイン時にトップ・会議録・静的画像が保護されること、許可された閲覧者だけ表示できることを確認します。予期しない一般公開が見えた場合は共有を止めて保護設定を確認します。
8. 初回後のPreviewは、mishima-migrationから対象環境を指定し、環境変数と実URLを読み戻して確認します。環境変数の変更後は再ビルドが必要です。Productionへの昇格・ドメイン追加・保護解除は別途承認事項です。
